## 作品范围

完整的第一章：醒潮港选择一位伙伴 → 烛苇原遇敌并捕捉 → 桥畔训练家伊沃 → 首座「回声灯塔」道馆 → 点亮航灯结局，可继续收集。目标 15–25 分钟，八种原创鸣兽、三位初始伙伴、六个队伍位置、图鉴、回复与自动/手动存档。

## 决定与理由

- 真实 3D 地形、建筑、桥、水与投影，透明像素 Sprite3D 角色。正交斜俯视、远近景倾斜模糊、柔光、暖灯冷影建立微缩摄影感，明确保留角色的像素边缘。
- 全部美术在 GDScript 中创建 ImageTexture、Mesh 与 Shader；字体由 5×7 字形点阵代码绘制。无外部图片、字体、音频、模型，也不调用生成式图片服务。
- 实时合成原创八小节动机，按探索/战斗重新配器和和声。避免随机选音，避免运行时生成整首长音频造成卡顿。
- 渲染采用兼容性路径和自写轻量屏幕倾斜景深，保证无需独立显卡；画面优先于复杂渲染栈。帧率限制 60，单 worker。
- 游戏内采用英文点阵字，中文交付文档提供对照。原因：不捆绑外部字体，同时保持界面字形完全由代码生成。
- 自由连续移动，草区按移动距离触发遭遇；回合制战斗包含普攻、属性招式、防御、换兽、捕捉、药剂和逃离。
- 捕捉与训练家胜利是道馆的明确前置。失败回港、全队回复，补给可以免费补足，杜绝耗尽资源后卡关。

## 模块接口与实施顺序

1. `creature_db.gd` / `game_state.gd` / `battle.gd`：数据与确定性规则。先写行为测试，覆盖三种开局、捕捉、换兽、胜负、等级与损坏存档。
2. `art.gd` / `pixel_font.gd`：八种鸣兽、人物三帧四朝向、材质点阵及完整英文字符；无文件载入。
3. `music.gd`：增量音频生成，主题与音效 API，可静音且 headless 安全。
4. `world.gd`：微缩岛屿、建筑、碰撞、草区、摄影机、3D 战斗舞台。
5. `main.gd` / `game_ui.gd`：标题、选择、探索、对白、战斗、图鉴、队伍、地图、结束状态与存档。
6. 导入检查 → 规则测试 → 集成完整旅程 → 真渲染截图与 UI 检查 → 独立代码审查 → 修复 → ZIP 解压复验。

## 验收边界

技术验证是本会话执行的工程验收，不代表用户已亲自验收。所有验证结果、未完成项及下一步执行人写入 `docs/v2/status.md`。本地 Godot.app 是用户原有工具，不属于交付源码，也不打入 ZIP。截图与测试日志仅作为交付验证附件，不作为游戏资源。
