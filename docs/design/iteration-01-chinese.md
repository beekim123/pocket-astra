# 第 01 轮：中文可玩实施计划

> **For agentic workers:** 按 `subagent-driven-development` 或 `executing-plans` 的逐项实施与审查方式执行。用户已授权当前会话自主扩展、验证后提交并推送，无需重新请求例行实施许可。方框是实施清单，不是已完成声明；实际状态写入 `docs/v2/status.md`。

**Goal:** 让完整第一章默认以简体中文游玩，提供可持久化的 English 切换，并保留原存档与玩法。

**Architecture:** 集中管理中英文显示文案，用稳定 ID 保持规则、动作和存档与语言独立。保留 ASCII 手绘点阵字体；含中文的文字通过操作系统 `SystemFont` 绘制，测量、换行和绘制共享同一度量。语言偏好单独保存，切换时刷新当前界面，不能重开旅程或重置战斗。

**Tech Stack:** Godot 4.7.2、GDScript、Compatibility 渲染、现有全代码 UI、运行时 SystemFont。

**Spec:** `docs/design/lanternwake.md` 的第一章范围，以及 `docs/design/expansion-roadmap.md` 的第 01 轮。原设计中“游戏内仅英文、所有字体均为自绘”的决定由本轮中文要求更新；其他素材和原创要求保持有效。

## 全局约束

- 简体中文为全新安装的默认语言；English 保留为完整语言，不只是局部英文标签。
- 项目不捆绑外部图片、音频、字体或模型。SystemFont 仅调用操作系统现有字体，不下载、复制、嵌入或打包字体文件。
- `GameState.SAVE_VERSION` 保持 `1`；`user://lanternwake.json` 的字段、物种 ID、属性 ID、动作 ID 和进度语义保持不变。
- 语言偏好使用独立设置文件；其缺失、损坏或未知语言值不会使旅程加载失败，也不会覆盖旅程档。
- 第一章仍保持三种初始伙伴、八种鸣兽、一个训练家、第一道馆、完整结局与结局后探索；本轮不加内容、调平衡或改地图。
- 所有验证由主代理检查整机计算预算后串行执行；默认一计算 worker，数值库线程为 1，长任务降低优先级。文档和只读审查可并行。
- 技术验证完成后审查、修复、提交并推送到 `https://github.com/beekim123/pocket-astra.git`；不用 force push。用户验收单独标注。

## 改动地图与职责

| 文件 | 本轮职责 | 保留的接口或约束 |
|---|---|---|
| 新增集中本地化模块 | 两种语言、完整文案目录、显示名称转换和偏好读写 | 只返回显示文本，不生成战斗随机数、不改进度；具体模块名称由主代理统一 |
| `scripts/pixel_font.gd` | ASCII 原字形与中文 SystemFont 分流；统一宽度、换行和行高 | 现有 `text`、`width`、`wrap` 调用不能彼此采用不一致的字宽；中文不能回落成问号 |
| `scripts/game_ui.gd` | 所有面板、按钮、地图、说明和统计文本；加入语言按钮 | `buttons` 中动作保持稳定英文 ID，按钮可点击和键盘可达 |
| `scripts/main.gd` | 加载偏好、切换语言、叙事对白、通知、战斗队列显示 | `handle_action`、模式名、返回模式、保存时机及胜负流程保持语义 |
| `scripts/creature_db.gd` | 鸣兽名、招式名、说明和属性的显示转换 | 物种索引、原始属性键和数值不可本地化成新的规则 ID |
| `scripts/battle.gd` | 战斗动态日志、结果和错误提示 | `begin`、`act`、随机种子及数值结果与语言无关 |
| `scripts/game_state.gd` | `quest()` 的玩家可见任务文本 | `save_game` / `load_game` 的版本、字段和事务式校验保持不变 |
| `scripts/world.gd` | 区域名、NPC/路牌互动名 | 角色 `role`、碰撞与坐标不因语言切换改变 |
| `tests/test_localization.gd`（建议新建） | 文案覆盖、参数、偏好、测量换行和规则独立性 | 测试使用专用文件，不读写玩家真实设置或旅程 |
| `tests/test_art.gd` / `tests/test_journey.gd` | 兼容字体契约和两种语言完整旅程 | 已有 ASCII、美术和完整通关验证不能被弱化 |
| `tests/render_capture.gd` / `tools/verify.sh` | 中文真实截图、语言切换截图及串行验证入口 | 截图输出项目外；不把截图当资源打包 |
| `README.md` / `docs/design/lanternwake.md` / `docs/v2/status.md` | 更新运行、字体来源、语言切换与真实结果 | 不继续声称游戏内仅英文或中文由手写点阵生成 |

## 任务 1：语言目录与偏好隔离

- [ ] 先列出玩家能看见的文字来源：标题、新游戏覆盖确认、初始伙伴、HUD、对白、战斗、队伍、图鉴、地图、设置、结局、短暂通知与失败提示。把每一项纳入集中目录或确定性显示函数。
- [ ] 为中英文词条校验键集合一致、无空值、格式占位符数量和类型一致；为含鸣兽名、伤害、等级、分钟、容器数量的模板准备实际参数样例。
- [ ] 实现默认 `zh_CN` 与 `en` 两个受支持值。未知值或坏文件使用中文默认值；不要把坏设置误判成坏旅程档。
- [ ] 语言偏好写入独立文件，例如 `user://lanternwake-settings.json`，只保存本轮需要的语言字段。采用临时文件写入后替换，失败保留内存中的可用语言并提供清楚反馈。
- [ ] 验证首次启动、保存英文、重新创建设置对象、重新加载英文、切回中文五个步骤；测试文件放到独立测试路径并在结束时清理。
- [ ] 保存前后读取一份旧版本旅程测试档，确认语言加载或切换未改动文件字节、队伍、图鉴、物资、坐标或进度。设置写入失败也不能触发旅程重写。

**验收结果：** 单独切换语言只改变显示和独立偏好。两种语言返回同一组战斗结果、动作可用性和任务阶段。

## 任务 2：真实中文绘制和排版

- [ ] 保留原 ASCII 字形字典及像素绘制路径。含中文或中文标点的文本选择 SystemFont，使用操作系统可用的中文字体及系统回退；字体对象缓存复用。
- [ ] 中文字体来源在 README 中写明“运行时使用系统字体”，不能继续笼统写“全部字体由源代码生成”。未验证的平台只声明可使用系统回退，不声明所有操作系统都已经通过。
- [ ] 同一个文字绘制路径负责测量宽度、行高、基线与实际绘制。检查现有 `_center`、`_button`、toast 宽度和 `_paragraph`，不能只把 `F.text` 换成字体绘制而保留 ASCII 的固定宽度假设。
- [ ] 中文按可用像素宽度换行，英文按单词优先、超长词逐字符折行；两者支持显式换行。保留 ASCII 数字、快捷键与中文混排，避免字符越界或丢字。
- [ ] 测量测试覆盖“灯潮纪”、中文全角标点、`HP 12 / 35` 混排、空字符串、显式换行、极窄边界和长战斗描述；每行实测宽度不得超出约定框宽。
- [ ] 根据实际行高调整对白和战斗信息区，而不是仅缩小所有中文。长对白分段仍保留完整意思；控件文字在目标 1280×720 下清楚、无重叠，按钮高度容纳字体。
- [ ] 对正文使用的中文字符执行系统字形可用性检查，并在真实图形环境确认标题、正文和标点没有方框、问号替代或缺字。无法满足时不能把中文候选标为通过。

**验收结果：** 中文是真实可读的画面。英文的 ASCII 点阵外观、美术缓存和像素动画测试继续通过。

## 任务 3：完整显示覆盖与切换行为

- [ ] 标题页提供可见的语言切换入口；探索的设置页提供同一入口，标记当前语言。切换后保持当前页面、选择状态以及游戏进度；以键盘和鼠标分别验证可达性。
- [ ] 全面替换 `game_ui.gd` 的显示常量，包括底部控制提示、物资标签、等级、生命、经验、回合、战斗种类、属性倍率、未知图鉴、释放确认及完成统计。
- [ ] 本地化 `main.gd` 的全部叙事与提示；本地化 `battle.gd` 中普通/专属攻击、命中、捕捉、换兽、防御、回复、升级、逃离、不能行动及胜负日志，格式参数使用对应语言的显示名。
- [ ] 本地化 `quest()`、区域标题、NPC 身份、地图标注和鸣兽资料。保留 `starter`、`captured`、`rival`、`gym` 等内部状态键以及 `strike`、`skill` 等动作键。
- [ ] 统一中文术语：鸣兽、回声容器、药剂、普通攻击、专属技、防御、换兽、捕捉、逃离、队伍、图鉴、第一盏灯印记。八种中文名沿用 README 的烛尾兽、帆溪獭、苔铃鹿、愿灯蛾、卵石甲、苇锋鹭、霆风鳐、夜辉鸮。
- [ ] 明确显示快照边界：如果对白或战斗日志在创建时已经成为字符串，语言切换不得留下整页旧语言。优先保存文案键和参数到显示边界；如保留字符串队列，则仅在允许切换的安全界面刷新所有仍可能显示的队列及短暂通知，不重放战斗动作或推进对白。
- [ ] 对所有玩家可见来源做覆盖扫描和人工复核。允许快捷键、品牌英文名与约定缩写，不允许未翻译的完整英文教学句、错误信息或动态日志留在中文模式。

**验收结果：** 从标题到结局全程无需理解英文；切到 English 后同一内容也完整可读。状态机和战斗规则没有因翻译改变。

- [ ] 在启动计算前读取当前全机进程，确保整机预算有余量；由主代理独占本轮验证队列，子代理只做源代码或结果审查。
- [ ] 把本地化测试加入 `tools/verify.sh` 的串行调用链，执行 `sh tools/verify.sh`。导入、规则、旅程、美术、音频和启动原有检查继续执行，出现错误或警告按现有规则判失败。
- [ ] 完整旅程至少分别运行中文、英文各一次：新旅程 → 介绍 → 选伙伴 → 移动过桥 → 遭遇与首捕 → 训练家 → 回复补给 → 道馆 → 结局 → 返回探索 → 图鉴 → 保存重载。三种初始伙伴的规则通关回归继续保留。
- [ ] 真实图形环境逐项检查中文标题、有旧档覆盖确认、三伙伴页、长对白、探索 HUD、战斗日志与七个动作、战斗换兽、队伍释放确认、已知/未知图鉴、地图、设置和结局。截图写到项目外，并记录使用的字体与分辨率。
- [ ] 在标题切到英文并重启检查持久化，再进入探索设置切回中文；核对语言按钮、toast、区域名和界面宽度即时更新。若测试会读默认设置，先隔离测试配置，不能改动玩家偏好作为测试副作用。
- [ ] 使用实际图形和音频设备运行正常关闭验证；确认中文字体资源退出、音频停止和保存处理没有新增错误或泄漏警告。
- [ ] 独立审查关注四项：遗漏文案与格式占位符、中文裁切、语言和规则耦合、旅程档或玩家设置被测试覆盖。修复后只重跑相关检查，再按需要执行最终串行全套。
- [ ] 更新 README、设计决定和状态；记录实际通过数量、日志、中文画面证据、未验证平台以及“用户验收未进行”。旧版 2,100 项结果不能冒充新增中文验证结果。
- [ ] 检查提交文件范围与差异，确保没有系统字体、生成图片、引擎本体、缓存或真实存档。提交中文轮，再正常推送；记录提交 SHA 与远端结果。推送失败时保留本地提交，明确原因和最近可执行步骤，不把本地提交说成已发布。

**验收结果：** 中文轮成为已验证、已审查、已提交并已推送的独立可玩版本；若任何一项尚未完成，状态明确保留在候选或待验证阶段。

## 源码审查发现的高风险位置

`PixelFont.width()` 当前按每字符 `6 * size` 估算，`wrap()` 当前按空格拆词；中文段落会把整个句子当成长词，且现有 `7 * size` 行高不足以说明系统中文字形实际高度。必须一起处理绘制、换行、居中和按钮位置。

`CreatureDB.species()` 同时向规则层提供 `element`、数值和显示名；本地化不能把 `element` 改成中文后继续传入 `effectiveness()`。物种显示名称应由 ID 取得，避免依赖翻译名称反查物种。

`main.gd` 的 `dialogue`、`battle_queue`、`battle_lines`、`area_text` 与 `toast` 都会缓存字符串。只在绘制层翻译固定 UI 文案，会漏掉这些动态快照；切换语言时需明确刷新边界。`render_capture.gd` 也含独立英文战斗样例，必须随截图测试更新，不能仅以静态中文标题代表全覆盖。

`game_ui.gd` 的图鉴总数和网格目前为八种硬编码，本轮不扩物种，保留即可；第三轮新增物种前必须改成数据驱动。避免把不相关的图鉴重构夹在中文轮里扩大回归范围。

当前无需你操作。下一步由主代理实施本计划、执行串行验证与独立审查，完成提交推送后进入第 02 轮浅鸣潮池救援；详细进度和执行人同步记录在 `docs/v2/status.md`。
